# مونتاج — أدوات المصمم للمطبعة

موقع عربي فيه أربع أدوات:

- **قوالب الأكواب**: ثمانية مقاسات من 4oz إلى 24oz، مع معاينة وتخصيص قالب الفرد وتنزيله SVG بأبعاده الفعلية.
- **حاسبة الأوراق**: كم قطعة تطلع من الورقة، وعدد الأوراق والتكلفة، ومقارنة كل مقاسات الورق، وتنزيل المونتاج SVG.
- **حاسبة الاستيكرات**: العدد في المتر الطولي والمربع، وطول الطباعة والتكلفة، وتنزيل متر واحد SVG للقص.
- **حاسبة الأكريليك**: العدد في اللوح أو سرير الليزر، والوزن والتكلفة، وتنزيل ملف القص SVG.

بوابة واحدة `/login` لاختيار الإدارة أو المصممين. يبدأ الدخول بكلمتي `TEAM_CODE` و`ADMIN_KEY` الحاليتين؛ وبعد تغييرهما من الإدارة تكون النسخ المشفّرة في Redis هي المرجع. الجلسات عشوائية، محددة المدة، مخزنة في Redis، ومحمية بكوكي HttpOnly. الإدارة تدخل أدوات المصمم من دون رمز إضافي، والمصمم لا يدخل لوحة الإدارة.

## البنية

| المسار | الوصف |
|---|---|
| `public/` | الموقع بعد البناء (يُنشأ تلقائيًا في Vercel) |
| `src/admin.html` | لوحة المستخدمين على الرابط `/admin` |
| `api/signup.js` | يسجّل البريد عند الدخول ويحسب الزيارات |
| `api/stats.js` | يعرض المستخدمين لصاحب المفتاح `ADMIN_KEY` فقط |
| `src/app.html` | الأدوات |
| `src/login.html` | شاشة دخول الفريق |
| `api/favorites.js` | مفضلة مشتركة للفريق في Redis؛ تتطلب جلسة صحيحة |
| `src/assets/workspace.js` | حفظ المقاسات وتطبيقها ومقارنة ثلاثة توزيعات |
| `src/build.mjs` | يبني `public/` من ملفات `src/` |

## الإعداد على Vercel

1. استورد المستودع في Vercel. إعدادات البناء موجودة في `vercel.json`.
2. من تبويب **Storage** أضف قاعدة **Upstash for Redis** واربطها بالمشروع (تضيف `KV_REST_API_URL` و`KV_REST_API_TOKEN`).
3. أضف متغيري البيئة `ADMIN_KEY` و`TEAM_CODE` بقيم سرية، ثم أعد نشر المعاينة.
4. افتح `/admin` وأدخل المفتاح لرؤية عدد المستخدمين وتنزيلهم CSV.

## التعديل

عدّل `src/app.html` أو `src/login.html` ثم شغّل:

```bash
node src/build.mjs
```

## المفضلة والمقارنة

في الأوراق والاستيكرات والأكريليك، اكتب اسمًا ثم اضغط «حفظ المقاس الحالي». تُحفظ إعدادات العملية في Redis وتتوفر للفريق على الأجهزة الأخرى بعد تحديث المفضلة. الحذف يزيل المقاس من مفضلة الفريق. الحد الأقصى 100 مقاس مشترك.

اضغط «إضافة التوزيع الحالي للمقارنة»، ثم غيّر المدخلات وأضف بديلًا. يمكن تثبيت ثلاثة توزيعات لكل حاسبة، مع المدخلات والنتائج والرسم وإعادة تطبيق أي منها. المقارنة مؤقتة وتُمسح بإعادة تحميل الصفحة. تكلفة كل بديل تعتمد على السعر الذي أدخلته، ولا تفترض تساوي أسعار الألواح أو الأوراق.

## التحقق

`node --test tests/api.test.mjs` يختبر الدخول وحماية المسارات والصلاحيات والمفضلة وحساب هامش البيع وتغيير كلمة المرور وإبطال الجلسات مع محاكاة Redis. هذا لا يغني عن اختبار الحفظ الفعلي على المعاينة بعد تسجيل الدخول. لا تدمج أو تنشر للإنتاج قبل مراجعة المعاينة.

## الإدارة والتسعير

تبويبات الإدارة: نظرة عامة، الخامات والأسعار، الربح والصلاحيات، الفريق والزيارات، الدخول والأمان. أضف تكلفة الوحدة الصحيحة (ر.س/سم² أو ر.س/قطعة) لكل خامة قبل اعتماد عروضها. لا نفترض تكاليف من أسعار البيع. تكاليف الشراء لا تظهر في استجابات المصمم.

هامش الربح = (سعر البيع − التكلفة) ÷ سعر البيع. سعر البيع المطلوب = التكلفة ÷ (1 − الهامش). السياسة الأولية 20% حد أدنى، 35% افتراضي، 70% حد أعلى؛ راجعها من الإدارة. يسمح خيار designerCanEdit للمصمم بتغيير سعر العملية أو هامشها ضمن الحدود؛ الخامات المقفلة تستخدم السعر الرسمي فقط. الخادم يعيد الحساب ويرفض السعر غير المطابق. الإجمالي يُقرب للأعلى لأقرب هللة لحماية الحد الأدنى.

كلمات المرور الجديدة تُخزّن باستخدام scrypt مع salt عشوائي. التغيير يحتاج كلمة مرور الإدارة الحالية ويُبطل جلسات القسم القديمة. لا تُغير هذه النسخة قيم Vercel الأصلية؛ بعد الحفظ في Redis تصبح هي المرجع لهذه النسخة. جلسة الإدارة 8 ساعات والمصممين 12 ساعة. الرجوع إلى كود قديم لا يضمن تطبيق كلمات المرور المحفوظة الجديدة.

أدوات المصمم السريعة تشمل تحويل سم/ملم/متر، قائمة مراجعة قبل الطباعة، اختصارات الحاسبات، المفضلة المشتركة ومقارنة التوزيع. المقاسات المفضلة تحفظ المقاسات والخامة، وتعيد تطبيق السياسة والأسعار الحالية؛ لا تحفظ تجاوزات الربح أو أسعارًا قديمة.
