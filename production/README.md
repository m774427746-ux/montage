# أسباركس — خدمة إنتاج المطبعة المحلية

هذه إضافة للمستودع الحالي، وليست منصة بديلة. قاعدة PostgreSQL المحلية هي مصدر
الحقيقة. واجهات المصمم والموظف محلية؛ تبويب الإدارة السحابي يعرض نسخة متابعة.

## وضع التسليم

الكود قابل للتشغيل مع إعداد الاتصال، واجتاز اختبارات PostgreSQL المعزولة والمتصفح.
**ليس اعتماد تشغيل فعلي للمطبعة:** لم يُختبر جهاز مصمم آخر، برنامج الطباعة، إعادة
تشغيل Windows، أو قاعدة asbarix_production. لا توجد أسعار أو حسابات افتراضية.

## الإعداد على Lenovo

1. احتفظ بالإصدار كاملًا، لأن الخدمة تستورد محرك التسعير من `api/_pricing.js`.
   استخدم Node.js 22 أو أحدث وPostgreSQL 16 الموجودين. لا تعد تثبيت قاعدة البيانات.
2. من مجلد `production` شغّل `npm ci --omit=dev`.
3. انسخ `config.example.env` إلى مسار خاص خارج Git، مثل
   `D:\ASBARIX-SERVER\config\production.env`. ضع كلمة المرور فيه محليًا فقط.
   استخدم URL encoding لكلمة المرور في DATABASE_URL. لا تشارك الملف في المحادثة.
4. اختر مجلد بيانات جديدًا، مثل `D:\ASBARIX-SERVER\production-data`؛ لا تضعه فوق
   ملفات Canon/Laser/SkyColor الحالية. أسماء التخزين مستقلة عن اسم ملف العميل.
5. نفّذ من مجلد production:

```powershell
node --env-file=D:\ASBARIX-SERVER\config\production.env src/cli.mjs check
node --env-file=D:\ASBARIX-SERVER\config\production.env src/cli.mjs migrate
```

إذا لم يملك `asbarix_app` صلاحية إنشاء Schema، يجهز مسؤول PostgreSQL Schema باسم
production ويمنح المستخدم ملكيته. لا تمنح SUPERUSER، ولا تعدل pg_hba لفتح الشبكة.

6. ضع BOOTSTRAP_USER وBOOTSTRAP_NAME وBOOTSTRAP_PASSWORD مؤقتًا في ملف الإعداد
   المحمي، ثم شغّل `node --env-file=... src/cli.mjs create-admin` واحذف قيمة
   BOOTSTRAP_PASSWORD بعد النجاح. الحد الأدنى 12 محرفًا؛ لا توجد كلمة مرور جاهزة.
7. شغّل `node --env-file=... src/server.mjs`. افحص
   `http://127.0.0.1:3000/health` ثم افتح الواجهة المحلية وسجّل دخول الإدارة.
8. اعتمد الخامات وأسعارها وخياراتها، وأنشئ حسابًا مسمى لكل مصمم وموظف. يمكن إضافة
   الماكينات. الخيارات التي يعتمدها المسؤول هي وحدها المعروضة والمقبولة من API.

## الشبكة والأمان

الإعداد الافتراضي يستمع إلى loopback فقط. استخدام أجهزة أخرى يحتاج وكيل HTTPS
محليًا بشهادة موثوقة لدى أجهزة المطبعة، وتحديد LOCAL_ORIGIN بعنوانه. يمكن إبقاء
Node على loopback وتشغيل الوكيل على عنوان الشبكة؛ لا تفتح المنفذ 5432.
تغيير الجدار الناري، تثبيت شهادة أو تعديل صلاحيات المجلدات يتطلب موافقة المسؤول.
لم ينفّذ المثبّت أيًا منها تلقائيًا. لا توجد حاجة إلى inbound tunnel أو port forwarding.

امنح حساب خدمة Windows قراءة الكود وملف الإعداد، وتعديل مجلد البيانات والسجلات
فقط. امنع مستخدمي الشبكة من كتابة المجلد مباشرة، أو إنشاء junctions/symlinks فيه.
الملفات PDF/PNG/JPEG/TIFF فقط، تُفحص البصمة والتوقيع؛ هذا ليس فحص برمجيات خبيثة.
ينبغي أن يبقى فحص Microsoft Defender مؤسسيًا مفعّلًا على التخزين.

## التشغيل التلقائي

`windows/Install-Service.ps1` يجهز خدمة WinSW تلقائية، بحساب LocalService وإعادة
محاولة بعد الفشل. أحضر WinSW من مستودعه الرسمي https://github.com/winsw/winsw
وتحقق من SHA-256 للإصدار الذي تعتمده، ثم مرّر مساره وبصمته وملف الإعداد للمثبّت.
ينشئ مجلد خدمة جديدًا فقط ويرفض الكتابة فوق مجلد قائم. تشغيله يحتاج صلاحيات
مسؤول Windows وموافقة على تثبيت الخدمة. لا يشغّلها قبل مراجعة ACL.

```powershell
Start-Service AsbarixProduction
Stop-Service AsbarixProduction
Restart-Service AsbarixProduction
Get-Service AsbarixProduction
```

السجلات تدور تحت مجلد خدمة Windows/logs، ولا تحتوي كلمات مرور أو محتوى الملفات.
للتحديث: أوقف الخدمة، احتفظ بإصدار الكود السابق، ثبت الإصدار الجديد بنفس مساره
أو عدّل XML بعد المراجعة، ثم `npm ci --omit=dev` وmigrate وابدأ الخدمة وافحص health.
لا ترجع migrations للخلف فوق بيانات حقيقية؛ استخدم استعادة معتمدة عند الحاجة.

## الربط السحابي

لا يُفعّل تلقائيًا. أنشئ سرًا عشوائيًا 32 بايت على الأقل في مدير الأسرار. ضع القيمة
نفسها في SYNC_SECRET محليًا وPRODUCTION_SYNC_SECRET في Vercel Preview أولًا.
ضع SYNC_URL على `/api/production` في Preview الموافق. لا تستخدم Production قبل
اعتماد الإصدار. النشر المحمي من Vercel قد يحتاج إعداد وصول آلي مصرح به؛ لا تعطل
حمايته. عدم الوصول لا يعطل الطلبات المحلية، بل يُبقي outbox لإعادة المحاولة.

توقيع HMAC يشمل الزمن وnonce والرسالة، مع رفض إعادة التشغيل ونسخ الأحداث القديمة.
لا تُرسل ملفات أو مسارات أو تكاليف شراء. تُعرض الأسعار الإجمالية وحالات نقص السعر.
كل الطلبات السحابية للإدارة محمية بجلسة الإدارة الحالية. لا يُسمح بتعديل حالات
التنفيذ من السحابة في هذا الإصدار.

تنزيل كتالوج الخامات السحابي لا يعني تفعيل كل مادة على ماكينة. لاستيراد مادة
بعد المزامنة، يربط المسؤول معرفها بالماكينة صراحة:

```powershell
node --env-file=... src/cli.mjs import-cloud-material CLOUD_ID laser LOCAL_ID
```

هذه عملية لقطة معتمدة يدويًا. لا تعيد تسعير الطلبات القديمة. الأكريليك يستخدم
محرك التسعير الحالي؛ المواد الأخرى تستخدم أسعار وحدات يعتمدها المسؤول محليًا.
إذا غابت التكلفة أو تكلفة التشغيل، يبقى هامش الربح مجهولًا. اعتمد 0 للتشغيل فقط
عندما يكون هذا قرارًا صحيحًا؛ لا يُفترض الصفر من تلقاء النظام.

## الأرشفة والسعة

المسار: `production-data/archive/YYYY/MM/DD/MACHINE/ORDER_UUID/FILE_UUID.bin`.
تاريخ الرياض. يُنسخ الملف دون استبدال، ثم تُفحص SHA-256 وfsync قبل اعتماد المسار
في transaction. تبقى النسخة المصدرية حاليًا للحماية من الفشل؛ لا يوجد حذف تلقائي.
لذلك احسب مساحة نسختين لكل ملف. هذا الإصدار لا ينقل ملفات المجلدات القديمة.
تغيير STORAGE_ROOT يحتاج نقلًا إداريًا موثقًا مع التحقق من البصمات والخدمة متوقفة؛
تغيير الإعداد وحده لا ينقل الملفات. التخزين الجديد لا يحتفظ بملفات وهمية.

## النسخ الاحتياطي والاستعادة

`windows/Backup.ps1` يشترط وسيطًا على قرص فعلي مختلف ويوقف خدمة الإنتاج أثناء
pg_dump ونسخ الملفات، ثم يعيد تشغيلها. لا يعد مجلدًا في القرص نفسه نسخة كافية.
النسخة تشمل Schema الإنتاج وملفات البيانات وmanifest بالبصمات؛ لا تشمل أسرار
البيئة، ويجب حفظها منفصلة لدى المسؤول. لا توجد جدولة مثبتة أو وسيط مفترض.

```powershell
.\windows\Backup.ps1 -EnvironmentFile D:\ASBARIX-SERVER\config\production.env -BackupRoot E:\AsbarixBackups -StorageRoot D:\ASBARIX-SERVER\production-data
```

للتدريب على الاستعادة، أنشئ قاعدة **فارغة منفصلة**، وحدد RESTORE_DATABASE_URL
وRESTORE_BACKUP وRESTORE_STORAGE_ROOT (مجلد غير موجود) في بيئة محمية، ثم شغّل
`node --env-file=... src/backup.mjs restore`. ترفض الأداة قاعدة فيها جداول أو نفس
رابط قاعدة التشغيل. لا تستخدمها فوق قاعدة المطبعة. تحقق من عدد الطلبات، تاريخ
الحالات، بصمات الملفات وتنزيلها قبل أي تغيير تشغيل. تبديل الخدمة إلى نسخة مستعادة
قرار منفصل يحتاج موافقة المسؤول. لا يتطلب التدريب حذف القاعدة الأصلية.

## الاختبارات

```powershell
node --test tests/api.test.mjs tests/production-cloud.test.mjs
node src/build.mjs
node tests/acrylic-tools.mjs
.\production\test\run-isolated.ps1
```

تُنفذ من جذر المستودع بعد `npm ci --prefix production`. الاختبار الأخير ينشئ
cluster PostgreSQL منفصلًا بمصادقة SCRAM على loopback:55439، وليس قاعدة المطبعة.
يستخدم Edge headless لاختبار الإرسال والتنزيل وRTL/LTR وعرض الهاتف. يحفظ مجلد
cluster التشخيصي تحت work ويوقفه في النهاية. لا تستخدم TEST_DATABASE_URL لقاعدة
حقيقية؛ الاختبارات تنشئ حسابات وطلبات اصطناعية وقاعدة restore_drill.

المتبقي للقبول التشغيلي: اعتماد ملف اتصال المطبعة، إعداد الأسرار وHTTPS، اختبار
جهاز المصمم وبرنامج الطباعة، اختبار انقطاع/عودة كهرباء عملي وإعادة تشغيل Windows،
تحديد قرص النسخ الاحتياطي واعتماد جدولته، واختبار مزامنة Preview الفعلية.
